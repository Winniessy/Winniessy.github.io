# Ollama 模型移植与本地部署记录

最近在用 Ollama 做模型移植，过程中发现，“把模型跑起来”只是第一步。真正需要整理的是：模型原本是什么格式，Ollama 能不能直接加载，提示词模板是否匹配，以及本地设备能不能承担推理开销。

这篇先把目前用到的流程记下来，后面再根据实际模型和设备补充测试结果。

## 一、先确认模型能不能直接使用

Ollama 里的 `FROM` 并不是万能的转换工具。模型本身需要是 Ollama 支持的格式，或者先转换成可加载的格式。

常见情况大致有两种：

- 已经是 GGUF 文件，可以在 `Modelfile` 里直接引用；
- 是 Transformers / Safetensors 等格式，需要先确认架构是否支持，必要时进行转换或量化。

所以拿到一个模型后，第一步不是马上执行 `ollama create`，而是先确认：

```text
模型架构是什么？
原始精度是什么？
有没有量化版本？
目标设备的内存和显存够不够？
```

如果模型架构不在运行时支持范围内，后面的 `Modelfile` 写得再正确也没有用。

## 二、用 Modelfile 描述模型

一个最简单的 `Modelfile` 可以这样写：

```text
FROM ./model.gguf

PARAMETER temperature 0.7
PARAMETER num_ctx 4096

SYSTEM """
你是一个可靠的助手，回答问题时尽量清晰、准确。
"""
```

这里的 `FROM` 指向模型文件，`PARAMETER` 用来设置推理参数，`SYSTEM` 用来补充系统提示词。

如果原模型有自己的聊天模板，不能简单套用一份模板。模板不匹配时，常见表现包括：

- 模型不按预期回答；
- 每轮对话重复输出角色标记；
- 输出突然停止，或者把提示词也当成回答内容；
- 中文和多轮对话效果明显变差。

因此移植时需要把模型原本使用的 prompt 格式一起确认清楚。对于聊天模型，模板通常和模型架构、训练方式有关，不能只看文件后缀。

## 三、创建和运行模型

准备好模型文件和 `Modelfile` 后，可以执行：

```bash
ollama create local-model -f Modelfile
ollama list
ollama run local-model
```

`local-model` 是自己取的名字。创建成功后，先用几条固定问题做人工验证，不要一开始就只看模型能不能输出文字。

例如可以固定测试：

```text
1. 简单事实问题
2. 一段代码解释
3. 中文和英文混合输入
4. 多轮追问
5. 较长上下文
```

这样比较容易判断问题到底来自模型本身、提示词模板，还是推理参数。

## 四、命令行之外的 API 验证

Ollama 启动后，可以通过本地 API 调用模型：

```bash
curl http://localhost:11434/api/generate -d '{
  "model": "local-model",
  "prompt": "解释一下什么是 DMA",
  "stream": false
}'
```

API 验证的价值在于，它更接近后续程序集成的使用方式。除了看回答内容，还应该记录：

- 首 token 等待时间；
- 整体生成速度；
- 内存或显存占用；
- 长上下文下是否变慢或报错；
- 多次运行结果是否稳定。

## 五、移植时比较容易遇到的问题

### 1. 创建模型时报架构不支持

这通常不是路径写错，而是模型架构或文件格式暂时不能被当前运行时识别。需要确认模型来源、转换工具和 Ollama 版本，不能只改 `Modelfile` 解决。

### 2. 模型能运行，但回答格式很奇怪

优先检查聊天模板和系统提示词。尤其是从其他推理框架迁移过来的模型，原来的模板可能没有被自动带过来。

### 3. 运行时内存不够

可以从几个方向处理：

- 使用更低位宽的量化版本；
- 减小 `num_ctx`；
- 关闭不必要的并发请求；
- 确认模型是否实际落在 GPU 上，避免以为用了 GPU，实际全部跑在 CPU 上。

### 4. 输出速度很慢

需要区分是模型本身较大、上下文过长，还是硬件没有正确加速。先用短提示词测试，再逐步增加上下文和生成长度，比较容易定位原因。

## 六、目前对“模型移植”的理解

Ollama 的优势不只是提供一个运行命令，更重要的是把模型文件、提示词模板和推理参数组织成了一个可以重复创建的配置。

因此我现在更愿意把移植过程拆成三层：

```text
模型文件：能不能被运行时加载
Modelfile：如何组织提示词和推理参数
设备验证：速度、内存和实际效果是否满足要求
```

只有模型成功加载，并不代表移植完成。模板、资源占用和实际任务效果都验证过，才算真正跑通。

## 七、后续准备补充的内容

- 记录具体模型的来源、版本和量化方式；
- 对比 CPU、GPU 和不同量化版本的速度；
- 整理自己的 `Modelfile` 模板；
- 记录模型转换失败时的完整报错；
- 尝试通过 Python 或其他程序调用 Ollama API；
- 对比 Ollama 与其他本地推理框架的使用差异。
