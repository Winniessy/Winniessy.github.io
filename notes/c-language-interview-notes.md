> 这份笔记根据本次 C/C++ 笔试中出现的知识点整理，重点放在嵌入式软件、Linux、驱动类岗位常见的 C 语言基础。
> 不追求把标准细节全部展开，主要用于笔试复习和面试回顾。

## 1. 数组、指针与 `sizeof`

### 1.1 数组名和指针

定义：

```c
int a[5];
int *p = a;
```

在大多数表达式中，数组名 `a` 会退化为指向首元素的指针：

```c
a == &a[0]
```

因此：

```c
a[i] == *(a + i)
p[i] == *(p + i)

&a[i] == a + i
&p[i] == p + i
```

但是要注意，**数组不是指针**。在下面这些场景中数组不会简单退化：

```c
sizeof(a)
&a
```

例如：

```c
sizeof(a)      // 整个数组大小
sizeof(p)      // 指针大小
```

如果 `int` 为 4 字节：

```c
int a[5];
```

则：

```text
sizeof(a) = 20
```

而在 64 位系统中：

```text
sizeof(p) 通常为 8
```

---

### 1.2 `&a` 和 `a` 的区别

虽然它们打印出来的地址值通常一样，但类型不同：

```c
a       // int *
&a      // int (*)[5]
```

因此：

```c
a + 1
```

移动一个 `int`。

而：

```c
&a + 1
```

移动整个 `int[5]` 数组的大小。

## 2. 数组指针和指针数组

这是笔试高频题。

### 数组指针

```c
int (*arr_ptr)[10];
```

先看括号：

```text
(*arr_ptr)
```

说明 `arr_ptr` 是一个指针。

它指向：

```text
int[10]
```

所以叫**数组指针**。

---

### 指针数组

```c
int *ptr_arr[10];
```

这里先和：

```text
[10]
```

结合。

所以 `ptr_arr` 是一个数组，其中有 10 个：

```c
int *
```

即**指针数组**。

对应：

```c
sizeof(arr_ptr)
```

是一个指针的大小。

而：

```c
sizeof(ptr_arr)
```

是：

```c
10 * sizeof(int *)
```

记忆：

```text
int (*p)[10]   → p 是指针
int *p[10]     → p 是数组
```

# 3. 字符、字符串和 `sizeof`

例如：

```c
char c = 'A';
char *s = "A";
```

两者完全不同。

`c` 是一个字符变量：

```c
sizeof(c) == 1
```

而 `s` 是指针：

```text
s
↓
'A' '\0'
```

因此：

```c
sizeof(s)
```

得到的是**指针大小**，不是字符串长度。

通常：

```text
32 位系统：4 字节
64 位系统：8 字节
```

真正计算字符串长度使用：

```c
strlen(s)
```

对于：

```c
"A"
```

结果是：

```text
1
```

因为 `strlen()` 不统计末尾的 `'\0'`。

# 4. 字符串常用函数

常见函数：

| 函数           | 作用        |
| ------------ | --------- |
| `strlen()`   | 字符串长度     |
| `strcmp()`   | 比较字符串     |
| `strcpy()`   | 复制字符串     |
| `strcat()`   | 拼接字符串     |
| `strncpy()`  | 限制复制数量    |
| `strncat()`  | 限制追加数量    |
| `snprintf()` | 限制格式化输出长度 |

### 字符串比较

应该使用：

```c
strcmp(s1, s2)
```

返回值：

```text
0     两字符串相等
< 0   s1 小于 s2
> 0   s1 大于 s2
```

不要写：

```c
s1 == s2
```

因为这通常比较的是**两个指针的地址**。

# 5. 字符串与缓冲区安全

传统 C 字符串函数最大的风险之一就是：

> **缓冲区溢出（Buffer Overflow）**

例如：

```c
char buffer[10];
scanf("%s", buffer);
```

如果输入超过数组容量，就可能越界。

可以限制：

```c
scanf("%9s", buffer);
```

因为还需要给：

```c
'\0'
```

留一个字节。

更通用的方法：

```c
fgets(buffer, sizeof(buffer), stdin);
```

`fgets()` 最多读取：

```text
sizeof(buffer) - 1
```

个字符，并为字符串结束符留位置。

---

### `sprintf` 和 `snprintf`

不推荐：

```c
sprintf(buf, "%s", str);
```

因为它不知道 `buf` 有多大。

更推荐：

```c
snprintf(buf, sizeof(buf), "%s", str);
```

---

### `strncat` 也不是绝对安全

例如：

```c
strncat(dest, src, n);
```

其中 `n` 表示最多追加多少个源字符，而不是：

> “目标缓冲区大小”。

所以仍然要确保：

```text
dest 当前长度 + n + 1 <= dest 容量
```

---

### `strncpy` 的坑

```c
strncpy(dest, src, n);
```

如果：

```text
strlen(src) >= n
```

目标字符串可能**没有自动添加 `'\0'`**。

所以不能看到带 `n` 就认为一定安全。

# 6. `const` 与指针

这一部分要直接看 `const` 和 `*` 的位置。

## 6.1 指向常量的指针

```c
const int *p;
```

或者：

```c
int const *p;
```

含义一样：

```text
p 可以改变
*p 不能通过 p 修改
```

例如：

```c
p = &b;      // 可以
*p = 10;     // 不可以
```

---

## 6.2 常量指针

```c
int * const p = &a;
```

表示：

```text
p 不能改变
*p 可以改变
```

例如：

```c
*p = 10;     // 可以
p = &b;      // 不可以
```

---

## 6.3 指向常量的常量指针

```c
const int * const p = &a;
```

表示：

```text
p 不能改变
*p 也不能通过 p 修改
```

简单记忆：

```text
const 在 * 左边 → 指向的数据不能改
const 在 * 右边 → 指针自己不能改
两边都有       → 两个都不能改
```

# 7. 函数指针

```c
void (*signal_handler)(int);
```

分析顺序：

```text
signal_handler
```

```c
int (*func_ptr)(int, int);
```

```c
int add(int a, int b);
```

然后：

```c
func_ptr = add;
int ret = func_ptr(3, 5);
```

函数指针在嵌入式中非常常见，例如：

```text
驱动接口表
状态机
事件处理
```

# 8. C 语言函数参数传递

C 语言本质上只有：

> **值传递（Pass by Value，按值传递）**

例如：

```c
void func(int x)
```

调用函数时，传入的是参数值的副本。

因此：

```c
x = 10;
```

不会修改调用者中的变量。

---

### 指针传参

```c
void func(int *p)
{
    *p = 10;
}
```

这里仍然是**值传递**。

只是传进去的值恰好是一个地址。

通过这个地址：

```c
*p = 10;
```

可以修改调用者中的对象。

所以严格来说：

> C 没有 C++ 那种真正的引用传递。

---

### 数组作为函数参数

例如：

```c
void func(int arr[])
```

作为函数参数时会调整为：

```c
void func(int *arr)
```

因此传进去的不是整个数组副本。

# 9. 可变参数 `...`

例如：

```c
int sum(int a, int b, ...);
```

`...` 表示：

> 函数还可以接受数量不固定的额外参数。

但：

```text
a
b
```

仍然是固定参数。

C 语言通过：

```c
va_list
va_start
va_arg
va_end
```

读取可变参数。

最典型的例子就是：

```c
printf()
```

可变参数的缺点是：

> 类型检查能力较弱，需要调用者和函数约定参数类型。

---

# 10. 宏 `#define`

例如：

```c
#define PRODUCT(a, b) (a)*(b)
```

调用：

```c
PRODUCT(x + 1, y + 2)
```

预处理阶段只是做文本替换：

```c
(x + 1) * (y + 2)
```

宏函数应该尽量写成：

```c
#define PRODUCT(a, b) ((a) * (b))
```

即：

> 参数加括号，整个结果也加括号。

否则：

```c
#define MUL(a, b) a * b
```

遇到复杂表达式时可能因为运算符优先级产生错误。

另外尽量避免：

```c
MACRO(i++)
```

这种带副作用的参数，因为宏参数可能被展开多次。

# 11. 运算符优先级与整数运算

例如：

```c
5 * 6 / 4 + 8 % 3
```

`*`、`/`、`%` 优先级相同，从左到右：

```text
30 / 4 = 7
8 % 3 = 2
```

由于是整数运算：

```text
7 + 2 = 9
```

整数除法会直接舍弃小数部分。

常见位运算：

```text
&   按位与
```

例如：

```c
reg |=  (1U << 3);      // 第3位置1

```

# 13. Popcount：统计二进制中 1 的个数

`Population Count` 指统计一个整数中：

```text
bit = 1
```

的数量。

一种实现方式是查表：

```text
32 位整数
→ 拆成 4 个字节
→ 每个字节查 256 项表
→ 四个结果相加
```

固定 32 位整数只查 4 次：

```text
时间复杂度 O(1)
```

这种方式本质是：

> **空间换时间。**

不过现代 CPU 通常可能提供：

```text
POPCNT
```

之类的硬件指令，此时硬件指令通常更加高效。

# 14. 有符号数和无符号数

C 中一个非常典型的坑是：

```c
int a = -1;
unsigned int b = 1;
```

当相同等级的：

```text
int
unsigned int
```

进行运算或比较时，通常会把：

```text
int → unsigned int
```

因此：

```c
-1
```

会被转换成一个非常大的无符号整数。

所以 signed / unsigned 混合计算时要特别小心。

---

# 15. 整数溢出

假设 16 位二进制补码：

```text
short 范围：

-32768 ~ 32767
```

题库通常会认为：

```text
32767 + 1
→ -32768
```

因为：

```text
0111 1111 1111 1111
+                  1
--------------------
1000 0000 0000 0000
```

不过需要知道：

> 严格 C 标准中，signed 整数溢出不能简单依赖“补码回绕”。

因此工程代码中不要依赖 signed overflow。

无符号整数则按：

```text
模 2^N
```

回绕。

# 16. 枚举 `enum`

例如：

```c
enum State {
    IDLE,
    RUNNING,
    ERROR
};
```

枚举成员是有名字的整数常量。

默认：

```text
IDLE    = 0
RUNNING = 1
ERROR   = 2
```

也可以显式指定：

```c
enum State {
    IDLE = 10,

```

```text
有限选项
```

# 17. `struct` 结构体与内存对齐

例如：

```c
struct A {
    char c;
    int x;
};
```

成员本身：

```text
char = 1
int  = 4
```

但是：

```c
sizeof(struct A)
```

通常不一定是 5，而可能是 8。

原因是编译器可能插入：

> **Padding（填充字节）**

典型布局：

```text
char
1 byte

padding
3 bytes

int
4 bytes
```

---

### 为什么需要内存对齐？

主要目的是：

> 提高 CPU 访问内存的效率。

某些处理器对未对齐访问：

```text
速度下降
甚至产生异常
```

这也是嵌入式岗位常问的原因。

---

# 18. `#pragma pack`

某些编译器支持：

```c
#pragma pack(1)
```

降低结构体成员的对齐要求，使结构体更紧凑。

好处：

```text
减少空间
方便某些协议/文件格式映射
```

但代价可能是：

```text
未对齐访问
性能下降
可移植性下降
```

因此不能为了“省几个字节”就随意使用。

另外：

> `#pragma pack` 属于编译器相关行为，并非所有平台行为完全一致。

# 19. 位域 Bit-field

例如：

```c
struct Status {
    unsigned int ready : 1;
    unsigned int error : 1;
    unsigned int mode  : 2;
};
```

表示：

```text
ready 使用 1 bit
error 使用 1 bit
mode  使用 2 bit
```

优点是节省存储空间。

常见于：

```text
状态标志
协议字段
嵌入式控制结构
```

---

### 位域注意事项

不能对位域成员直接取地址：

```c
&status.ready     // 不允许
```

因为一个位域成员可能只占几个 bit，并不存在独立可寻址的字节地址。

另外：

> 位域的排列顺序、布局和对齐可能受编译器和平台影响。

因此做硬件寄存器映射时必须结合编译器和芯片手册，不能只凭 C 语法猜布局。

# 20. `struct` 和 `union`

## `struct`

结构体中的成员各自拥有自己的存储空间：

```c
struct Data {
    int a;
    char b;
};
```

`a` 和 `b` 可以同时保存不同的值。

---

## `union`

联合体中的所有成员：

> **共享同一块内存。**

例如：

```c
union Data {
    int i;
    char buf[4];
};
```

`i` 和 `buf` 从同一块地址开始。

因此：

```text
struct → 成员各占空间
union  → 成员共用空间
```

---

### `sizeof(union)`

联合体必须至少能够容纳：

> 最大的那个成员。

同时还要满足成员的对齐要求。

例如：

```c
union Data {
    int i;
    char str[4];
};
```

如果：

```text
sizeof(int) = 4
sizeof(char[4]) = 4
```

那么通常：

```text
sizeof(union Data) = 4
```

而不是：

```text
4 + 4 = 8
```

# 21. `malloc`、`calloc`、`realloc`

## malloc

```c
p = malloc(size);
```

作用：

> 动态分配一块内存。

新分配内存中的原数据未初始化。

---

## calloc

```c
p = calloc(n, size);
```

分配：

```text
n * size
```

字节，同时把分配的字节清零。

---

## realloc

```c
new_p = realloc(p, new_size);
```

作用：

> 调整已有动态内存块大小。

可能：

```text
原位置直接扩展
```

也可能：

```text
申请新空间
→ 拷贝旧数据
→ 释放旧空间
```

所以返回地址可能发生变化。

---

### `realloc(NULL, size)`

等价于：

```c
malloc(size)
```

---

### `realloc` 失败

失败时：

```text
返回 NULL
原来的 p 指向的内存仍然有效
```

因此不要直接写：

```c
p = realloc(p, new_size);
```

更稳妥：

```c
void *tmp = realloc(p, new_size);

if (tmp != NULL)
    p = tmp;
```

否则失败以后可能把原地址丢掉，造成内存泄漏。

---

# 22. 动态内存使用原则

嵌入式系统里并不是：

> 动态内存越多越好。

动态内存可能带来：

```text
内存碎片
分配失败
执行时间不确定
生命周期管理复杂
内存泄漏
```

所以实时系统、MCU、驱动代码中经常优先考虑：

```text
静态分配
固定大小内存池
预分配
```

是否使用动态内存要看场景，而不是完全禁止。

# 23. `rand()` 和 `srand()`

```c
rand()
```

生成：

```text
0 ~ RAND_MAX
```

之间的**伪随机整数**。

它不是密码学意义上的真随机。

---

### 设置随机种子

常见：

```c
srand(time(NULL));
```

即使用当前时间作为种子。

如果程序一直使用相同种子，那么：

> 生成的伪随机序列也相同。

---

### 生成 0～99

```c
rand() % 100
```

得到：

```text
0 ~ 99
```

之间的整数。

注意：

```c
rand() % N
```

严格来说可能存在：

> **Modulo Bias（取模偏差）**

普通笔试一般不深入考。

# 24. 文件操作

打开文件：

```c
FILE *fp = fopen("test.txt", "r");
```

成功：

```text
返回 FILE *
```

失败：

```text
返回 NULL
```

用完后应该：

```c
fclose(fp);
```

---

### 常见打开模式

| 模式   | 含义         |
| ---- | ---------- |
| `r`  | 读取         |
| `w`  | 写入，原文件内容清空 |
| `a`  | 追加         |
| `r+` | 读写         |
| `w+` | 读写，原内容清空   |
| `a+` | 读取 + 追加    |

其中：

```c
"a+"
```

允许读，同时所有写入会追加到文件末尾。

# 25. `fseek()` 和 `ftell()`

```c
fseek(FILE *stream, long offset, int whence);
```

第三个参数常见：

```text
SEEK_SET    从文件开头
SEEK_CUR    从当前位置
SEEK_END    从文件末尾
```

例如：

```c
fseek(fp, 0, SEEK_END);
```

将文件位置移动到末尾。

`fseek()` 成功时通常：

```text
返回 0
```

---

### `ftell`

```c
long pos = ftell(fp);
```

用于获取当前文件位置指示器的值。

普通二进制文件场景下通常可以理解为当前偏移。

# 26. `printf` 和缓冲区

标准输出连接终端时，通常是：

> **行缓冲（Line Buffered）**

因此：

```c
printf("hello\n");
```

遇到换行符时通常会触发输出刷新。

也可以主动：

```c
fflush(stdout);
```

---

### 不要依赖 `fflush(stdin)`

在标准 C 中：

```c
fflush(stdin);
```

不是通用、可移植的“清空输入缓冲区”方法。

不要把它当成标准写法。

### `%#x`

例如：

```c
printf("%#x", 10);
```

输出：

```text
0xa
```

`#` 会让十六进制结果带：

```text
0x
```

前缀。

# 27. `errno` 和错误处理

很多 C 库函数出错时会：

1. 通过返回值表示失败；
2. 同时设置 `errno`。

正确思路是：

```text
先检查函数返回值
↓
确认发生错误
↓
再查看 errno
```

而不是：

```c
func();

if (errno != 0)
```

就直接认为函数出错。

原因是：

> 函数成功后不一定会自动把 `errno` 清零。

所以 `errno` 里可能仍然保留之前的错误值。

---

# 28. `assert`

例如：

```c
assert(ptr != NULL);
```

它的用途是：

> 检查程序员认为正常情况下必须成立的条件。

适合：

```text
内部不变量
不可能出现的状态
开发期错误检查
```

不适合：

```text
用户输入错误
网络错误
文件不存在
正常业务失败
```

这些情况应该使用：

```c
if (...)
```

进行正常错误处理。

---

### `NDEBUG`

定义：

```c
#define NDEBUG
```

后再包含：

```c
#include <assert.h>
```

通常会禁用断言。

因此不要在 `assert()` 中写带副作用的代码，例如：

```c
assert(i++);
```

否则 Release 版本中这段逻辑可能直接消失。

# 30. 时间复杂度

经典 Fibonacci：

```c
int func(int n)
{
    if (n <= 1)
        return 1;

    return func(n - 1) + func(n - 2);
}
```

每次会产生大量重复递归。

时间复杂度是指数级，笔试通常选择：

```text
O(2^n)
```

更加严格地说增长速度接近：

```text
O(φ^n)
```

递归深度：

```text
O(n)
```

因此栈空间大约：

```text
O(n)
```

---

# 31. 哈希表复杂度

哈希表查询平均：

```text
O(1)
```

但发生严重哈希冲突时，最坏可能退化。

常见回答：

```text
平均：O(1)
最坏：O(n)
```

哈希表通常是：

> 用额外空间换取查询速度。

所以时间复杂度和空间复杂度并不是完全独立的。

# 32. 递归和迭代

把递归改成迭代，常见收益是：

```text
减少函数调用开销
减少递归栈空间
避免栈溢出
```

但：

> 不代表时间复杂度一定发生变化。

例如一个：

```text
O(n)
```

的递归算法改成循环以后，很可能仍然是：

```text
O(n)
```

只是常数开销和空间占用下降。

# 33. 二叉树：前序 + 中序求后序

如果节点值唯一：

```text
前序遍历 + 中序遍历
```

可以唯一确定一棵二叉树。

方法：

```text
前序第一个元素
→ 根节点

在中序序列中找到根
→ 左边属于左子树
→ 右边属于右子树

对子树递归重复
```

得到树后：

```text
左子树
→ 右子树
→ 根
```

就是后序遍历。

这个思路比直接背某一道题的结果重要。

# 35. 大小端与 `union`

例如：

```c
union Data {
    uint32_t value;
    uint8_t byte[4];
};
```

写入：

```c
value = 0x12345678;
```

在常见小端系统中内存顺序通常是：

```text
78 56 34 12
```

而大端系统则通常是：

```text
12 34 56 78
```

所以：

> 大小端描述的是多字节数据在内存中的字节排列顺序。

它与协议解析、网络通信、寄存器读写关系非常大。
