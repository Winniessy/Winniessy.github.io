# UART、I2C、SPI 与 SPI 菊花链通信总结

UART、I2C 和 SPI 是 MCU 项目中最常见的几种串行通信接口。它们的信号线、时序和错误表现差别很大，排查时不能只盯着软件配置，电平、线序、供电和波形同样重要。

这篇笔记按协议原理、常见问题和排查方法整理，最后单独记录 SPI 菊花链的工作方式。

## 1. 三种接口对比

| 项目 | UART | I2C | SPI |
| --- | --- | --- | --- |
| 类型 | 异步串行 | 同步串行 | 同步串行 |
| 典型信号线 | TX、RX | SDA、SCL | SCK、MOSI、MISO、CS |
| 双工方式 | 全双工 | 半双工 | 全双工 |
| 拓扑 | 点对点，RS485 可扩展 | 多主多从，地址寻址 | 单主多从，片选寻址 |
| 时钟 | 无，依靠双方约定的波特率 | 主机提供 SCL | 主机提供 SCK |
| 应答 | 无 | ACK/NACK | 无 |
| 电气特性 | 取决于 TTL、RS232 或 RS485 | 开漏输出加上拉 | 通常为推挽输出 |
| 常见速率 | 9600 bps 到几 Mbps | 100 kHz、400 kHz、1 MHz 等 | 几 MHz 到几十 MHz |

## 2. UART

### 2.1 协议原理

UART 没有时钟线，收发双方通过预先约定的波特率完成采样。以最常见的 8N1 为例，一帧数据包括 1 个起始位、8 个数据位和 1 个停止位，没有校验位。

```text
空闲  起始   D0 D1 D2 D3 D4 D5 D6 D7  停止  空闲
 1     0     ........数据........       1     1
```

需要注意的几点：

- 空闲状态通常为高电平，起始位是一个下降沿。
- 数据通常按照 LSB first 发送。
- 波特率、数据位、停止位和校验方式必须匹配。
- 接收端一般通过过采样，在数据位中间进行采样。
- 波特率误差过大时，越靠后的数据位越容易采样错误。
- TTL UART、RS232 和 RS485 的电平及物理层并不相同，不能直接混接。

UART 还可以使用硬件流控 RTS/CTS，或者软件流控 XON/XOFF。RS485 通常是差分半双工通信，还要额外控制收发方向。

### 2.2 常见错误

- **帧错误**：停止位电平不正确，常见原因是波特率、停止位配置不一致或线路噪声。
- **奇偶校验错误**：双方校验方式不一致，或者数据受到干扰。
- **溢出**：新数据到达时，CPU、FIFO 或 DMA 没有及时取走旧数据。
- **完全没有数据**：TX/RX 接反、没有共地、电平不匹配、GPIO 复用错误或 RS485 方向控制错误。
- **乱码**：波特率、时钟源、数据位、停止位或校验配置不一致。
- **间歇性丢包**：中断优先级太低、DMA 配置错误、FIFO 太小、流控未启用或线路质量较差。

### 2.3 排查方法

1. 先做环回测试，把 TX 和 RX 短接，确认 MCU 自发自收是否正常。
2. 检查线序：一端 TX 要接另一端 RX，RX 要接 TX，并且两端共地。
3. 确认物理层。TTL 连接 TTL，RS232 使用电平转换芯片，RS485 使用对应的收发器。
4. 用示波器测量位宽。115200 波特率下，一个 bit 的时间约为 8.68 us。
5. 用逻辑分析仪解码，确认起始位、数据位、停止位和校验位。
6. 把波特率从 115200 降到 9600。如果低速正常，通常需要检查时钟误差和信号完整性。
7. 检查 GPIO 复用、中断、DMA、FIFO 和接收缓冲区边界。
8. RS485 还要检查发送完成后的收发方向切换、终端电阻、差分线序和共地。

## 3. I2C

### 3.1 协议原理

I2C 使用 SDA 和 SCL 两根线。两根线都是开漏结构，必须通过上拉电阻回到电源电压。设备通过地址区分，数据传输过程中由接收方在第 9 个时钟周期返回 ACK 或 NACK。

基本时序如下：

- 总线空闲时，SDA 和 SCL 都为高电平。
- **START**：SCL 为高电平时，SDA 从高变低。
- **STOP**：SCL 为高电平时，SDA 从低变高。
- SCL 为低时改变 SDA，SCL 为高时 SDA 保持稳定。
- 每传输 8 个数据位，接着传输 1 个 ACK/NACK 位。
- 常见地址为 7 位地址，后面再加 1 位读写标志；也存在 10 位地址设备。
- 读寄存器时经常使用重复起始，不先发送 STOP 就切换到读方向。

典型的寄存器写操作：

```text
START → 从机地址 + W → ACK → 寄存器地址 → ACK → 数据 → ACK → STOP
```

典型的寄存器读操作：

```text
START → 从机地址 + W → ACK → 寄存器地址 → ACK
      → 重复 START → 从机地址 + R → ACK → 读数据 → NACK → STOP
```

I2C 还支持时钟拉伸和多主仲裁。总线电容越大，上拉电阻越大，上升沿就越慢，因此上拉电阻需要结合电压、总线长度、设备数量和速率选择。

### 3.2 常见错误

- **NACK**：设备地址错误、设备未上电、设备处于忙状态、寄存器地址错误、写保护或电压不匹配。
- **总线一直为低**：从机在传输过程中复位、上电时序异常，或者主机复位时把 SDA/SCL 留在异常状态。
- **仲裁丢失**：多个主机同时访问总线。
- **时钟拉伸超时**：主机驱动不支持时钟拉伸，或从机异常拉低 SCL。
- **时好时坏**：上拉阻值不合适、总线电容过大、连线过长、干扰严重或地线不可靠。
- **完全没有波形**：GPIO 没配置为开漏、没有上拉、设备没供电或控制器地址配置错误。

### 3.3 排查方法

1. 测量 SDA 和 SCL 的空闲电平，确认两根线都能被上拉到正确的 VCC。
2. 核对器件手册中的 7 位地址，注意代码中有些接口要求传入左移后的 8 位地址。
3. 用逻辑分析仪检查 START、STOP、第 9 位 ACK，以及 SCL 是否被从机拉低。
4. 观察 SDA/SCL 上升沿。如果边沿太慢，检查上拉阻值和总线电容。
5. 把速率从 400 kHz 降到 100 kHz，必要时进一步降速。
6. 检查主控和从机的电压，必要时使用电平转换器。
7. 确认寄存器读操作是否需要 repeated start。
8. 总线卡死时，可以把 SCL 临时配置为 GPIO，发送 9 个时钟脉冲，再发送 STOP，最后重新初始化控制器。
9. 总线上只保留一个从机，排查地址冲突以及某个设备把总线拉死的情况。
10. 最后检查超时、重试、DMA、中断优先级和时钟拉伸处理。

## 4. SPI

### 4.1 协议原理

SPI 通常使用四根线：

- **SCK**：时钟，由主机产生。
- **MOSI**：主机输出、从机输入。
- **MISO**：主机输入、从机输出。
- **CS/SS**：片选，通常为低有效。

SPI 是同步全双工接口。每个时钟周期内，主机和从机可以同时移出一位、移入一位。SPI 没有地址和 ACK，主机通过 CS 选择从机，因此主机并不知道从机是否真正理解了发送的数据，通常需要通过读取 ID 或状态寄存器确认通信结果。

多个从机共用 SCK、MOSI 和 MISO 时，每个从机一般使用独立 CS。未被选中的从机必须让 MISO 处于高阻态，否则可能与当前从机发生总线冲突。

### 4.2 SPI 四种模式

SPI 模式由 CPOL 和 CPHA 共同决定：

- CPOL 决定时钟空闲时的电平。
- CPHA 决定在哪个边沿采样数据。

| 模式 | CPOL | CPHA | 空闲电平 | 采样沿 | 移位沿 |
| --- | ---: | ---: | --- | --- | --- |
| Mode 0 | 0 | 0 | 低 | 上升沿 | 下降沿 |
| Mode 1 | 0 | 1 | 低 | 下降沿 | 上升沿 |
| Mode 2 | 1 | 0 | 高 | 下降沿 | 上升沿 |
| Mode 3 | 1 | 1 | 高 | 上升沿 | 下降沿 |

除了模式，还要核对以下参数：

- MSB first 还是 LSB first；
- CS 的有效电平；
- CS 建立时间和保持时间；
- 时钟频率上限；
- 数据在哪个时钟沿采样。

### 4.3 常见错误和排查方法

**完全没有数据**，先检查 CS 是否拉低、SCK 是否输出、GPIO 复用是否正确、从机是否供电以及片选线是否接对。

**数据错位或读写结果异常**，重点检查 CPOL/CPHA、MSB/LSB、采样沿和 CS 时序。很多器件的寄存器读写还要求 CS 在整个命令和数据阶段保持有效。

**MISO 冲突**，检查是否有多个从机同时使能，以及未选中的器件是否真的释放了 MISO。

**高速下不稳定**，检查线长、反射、地回流、串扰、时钟频率和建立保持时间。可以先把 10 MHz 降到 1 MHz 或 100 kHz，判断问题是否与信号完整性有关。

建议按下面的顺序排查：

1. 用逻辑分析仪同时抓取 SCK、MOSI、MISO 和 CS。
2. 先读取从机 Device ID，确认基本通信，而不是一开始就调复杂寄存器。
3. 做 MOSI-MISO 环回测试，验证主控 SPI 控制器和驱动配置。
4. 检查 CS 在整个传输期间是否保持有效，结束后才释放。
5. 降低时钟频率，确认低速下是否正常。
6. 检查共地、电源、去耦、线长、串联电阻和端接方式。
7. 最后再检查 DMA、片选控制、字节序、超时和缓冲区处理。

## 5. SPI 菊花链

### 5.1 连接方式

普通 SPI 多从机通常是每个从机单独使用一根 CS：

```text
主机 CS1 → 从机1 CS
主机 CS2 → 从机2 CS
主机 CS3 → 从机3 CS
SCK、MOSI、MISO 并联
```

菊花链则把多个从机的串行输入和串行输出首尾相接：

```text
主机 SCK  → 所有从机 SCK
主机 CS   → 所有从机 CS
主机 MOSI → 从机1 SI
从机1 SO  → 从机2 SI
从机2 SO  → 从机3 SI
...
从机N SO  → 主机 MISO
```

所有从机共用一个 CS，数据在各个从机内部像移位寄存器一样逐级传递。

### 5.2 工作原理

如果每个从机有 8 位移位寄存器，N 个从机就相当于一个长度为 N×8 位的移位寄存器。主机一次通信必须发送完整的数据帧，不能只发送其中一个从机需要的字节。

以“主机 → 从机1 → 从机2 → 从机N → 主机”的方向为例：

- 主机先发送的字节通常会到达最远端从机。
- 主机最后发送的字节通常进入离主机最近的从机。
- 读回时，通常先收到最远端从机的数据。
- 实际顺序还与器件的移位方向、MSB/LSB 配置和芯片手册定义有关。

因此，发送顺序不能凭直觉确定，应该按照器件手册中的级联时序验证。

### 5.3 优点和限制

优点：

- 节省 CS 引脚和 GPIO。
- 多个同类型器件可以共用一组时钟和片选信号。
- 所有器件可以在同一个 CS 周期内同步更新。
- 从机数量较多时，布线相对简单。

限制：

- 链上任意一个器件异常，都可能影响整条链路。
- 不能只访问某一个从机，每次都要收发完整链长的数据。
- 数据量随从机数量增加，延迟也会增加。
- 速率会受到最慢器件、级联传播延迟和链路长度限制。
- 器件必须明确支持级联，或者本身就是适合级联的移位寄存器。
- 数据顺序、位宽、复位状态和初始化帧必须保持一致。

### 5.4 菊花链排查

1. 先确认器件手册中有 daisy-chain、cascade 或 serial output 相关说明。
2. 用逻辑分析仪观察 MOSI 和 MISO，确认发送的是 N 个从机所需的完整位数。
3. 先只连接一个从机，再逐步增加到两个、三个，定位是哪一级开始异常。
4. 核对数据发送顺序，确认最先发送的数据应该落在哪个从机。
5. 检查所有从机的 CS 是否同时有效，传输期间是否发生抖动。
6. 检查所有从机是否处于一致的复位和初始化状态。
7. 先把时钟降到 100 kHz 到 1 MHz，排除传播延迟和信号完整性问题。
8. 怀疑某个器件时，可以替换该器件或临时旁路，观察整条链路是否恢复。
9. 检查多片器件的电源、去耦、电源时序和地回流。

## 6. 通用排查顺序

无论是 UART、I2C 还是 SPI，都可以先按照下面的顺序排查：

### 6.1 电源和地

确认供电电压、共地、去耦电容和上电时序。多片器件组成菊花链或总线时，还要确认每个器件都真正上电并退出复位。

### 6.2 电平匹配

确认 3.3 V 和 5 V 是否需要电平转换，RS232/RS485 是否使用了对应收发器，I2C 是否配置为开漏并接入上拉电阻。

### 6.3 线序和连接

检查 UART 的 TX/RX、I2C 的 SDA/SCL、SPI 的 MOSI/MISO/SCK/CS，确认没有接反、漏接或片选接错。

### 6.4 控制器配置

UART 重点看波特率、数据位、停止位和校验；I2C 重点看地址和速率；SPI 重点看模式、位序、时钟频率和 CS 极性。

### 6.5 抓取波形

示波器适合看电平、边沿和噪声，逻辑分析仪适合解码协议。重点观察 UART 的起始位，I2C 的 START、ACK 和 STOP，以及 SPI 的 CS、采样沿和数据位。

### 6.6 降速和隔离

高速不通时先降速。把总线上其他设备断开，只保留一个从机；UART 做环回，SPI 做 MOSI-MISO 环回，逐步排除硬件和配置问题。

### 6.7 软件路径

最后检查 GPIO 复用、中断、DMA、FIFO 溢出、超时重试、片选控制和缓冲区边界。很多“偶发通信错误”最终都与软件没有正确处理异常状态有关。

## 7. 总结

- **UART**：异步、无时钟、通常点对点，排查重点是波特率、TX/RX、共地和电平。
- **I2C**：两线开漏、有地址和 ACK，排查重点是上拉、地址、ACK 和总线死锁。
- **SPI**：同步全双工、没有地址和 ACK，排查重点是 CS、CPOL/CPHA、位序和 MISO 三态。
- **SPI 菊花链**：所有从机共用 CS，数据串联成一个长移位寄存器，节省引脚但增加数据量和故障定位难度。

实际调试时，先确认电源、地和电平，再看线序和配置，最后用波形验证时序。这样通常比直接反复修改驱动代码更快定位问题。
