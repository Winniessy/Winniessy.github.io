# Linux 虚拟内存、mmap 与 Camera DMA 零拷贝链路

在分析摄像头驱动和 DMA buffer 时，虚拟地址、页表、`mmap`、DMA 地址经常会同时出现。它们分别属于 CPU、内核和设备访问内存的不同层次，先把这些概念分开，再看完整的数据链路会清楚很多。

## 1. 虚拟地址、物理地址与页表

虚拟地址本质上是 CPU 使用的一个编号。CPU 访问虚拟地址时，MMU 根据页表把它转换成物理地址。

以 4 KB 页为例，一个虚拟地址可以拆成两部分：

```text
虚拟地址 = 虚拟页号 × 页大小 + 页内偏移

虚拟地址 = 0x7f8a3c001234
页大小   = 0x1000
虚拟页号 = 0x7f8a3c001
页内偏移 = 0x234
```

页内偏移由页大小决定。4 KB 页使用低 12 位作为偏移，因此虚拟地址除以 `0x1000` 得到虚拟页号，取余得到页内偏移。

页表可以理解为一组用于地址转换的数组，每一项叫页表项（PTE，Page Table Entry）。页表项记录虚拟页对应的物理页帧，以及读写权限、执行权限、是否有效等属性。

虚拟地址空间很大，通常不会用一张表一次性覆盖全部地址，而是使用多级页表。Linux 中常见的 4 KB 页配置可以抽象为：

```text
PGD → PUD → PMD → PTE → 物理页帧
```

在常见的 64 位配置中，每一级通常使用 9 位索引，也就是 512 个表项，每个表项 8 字节，一张页表正好占用 4 KB。不过具体级数、地址位宽和页大小取决于处理器架构以及内核配置，不能把 48 位地址、四级页表和 4 KB 页当成所有系统都固定如此。

## 2. 缺页异常

第一次访问某个虚拟地址时，MMU 如果发现页表项不存在或标记为无效，就会触发缺页异常，CPU 转入内核的缺页处理流程。

内核会先判断这个地址是否属于进程已有的 VMA（Virtual Memory Area，虚拟内存区域）：

- 不属于任何合法 VMA，通常会向进程发送 `SIGSEGV`。
- 属于匿名映射，内核可以分配物理页并建立映射。
- 属于文件映射，内核可以按需从文件读入对应内容。
- 属于设备映射，内核会进入对应驱动的映射处理流程。

处理完成后，内核把物理页信息填入页表并返回用户空间。CPU 会重新执行刚才失败的访问指令，这次 MMU 就可以完成地址转换。

这个过程对用户程序通常是透明的，也是虚拟内存按需分配和按需加载的基础。

## 3. `mmap` 预留的到底是什么

调用 `mmap` 后，内核首先在进程地址空间中找到一段合适的虚拟地址，并创建或调整一个 VMA。VMA 记录了这段区域的起止地址、访问权限、映射类型以及关联的文件或设备。

因此，普通的 `mmap` 返回时并不一定已经分配了全部物理内存，也不一定已经为每一页建立了页表项。可以把它理解为先登记一段地址范围，真正访问时再根据映射类型完成后续工作。

普通文件映射和匿名映射通常采用按需建立页表的方式。设备映射则由驱动的 `.mmap` 回调参与处理，常见流程如下：

```text
用户调用 mmap()
  → 内核创建或调整 VMA
  → 调用驱动的 .mmap 回调
  → 驱动把已有的 DMA buffer 映射到用户空间
  → 用户通过返回的虚拟地址访问同一块 buffer
```

摄像头驱动通常不会在用户第一次读写时重新分配一份数据，而是把已经准备好的 DMA buffer 映射给用户。具体实现可能使用 V4L2 videobuf2 提供的 DMA 内存操作、`dma_mmap_*()` 或其他架构相关的映射接口，不能简单概括成所有驱动都直接调用同一个函数。

## 4. `kmalloc`、`vmalloc`、CMA 与 DMA

这几个概念经常一起出现，但作用并不相同。

### `kmalloc`

`kmalloc` 返回内核虚拟地址，通常用于分配较小的内核对象。在常见配置下，分配得到的物理内存也是连续的，适合普通内核数据结构和小块 buffer。需要给设备做 DMA 时，仍然应该通过 DMA API 判断这块内存是否满足设备要求。

### `vmalloc`

`vmalloc` 返回虚拟地址连续、物理地址可以不连续的内存。它适合较大的软件 buffer，但不适合直接把返回的 CPU 虚拟地址当成设备 DMA 地址使用。

### CMA

CMA（Contiguous Memory Allocator）在系统启动时预留一部分可迁移内存，需要时用于分配连续的物理页。摄像头、显示和视频编解码等硬件经常需要较大块的连续 DMA 内存，因此可能使用 CMA。

### DMA

DMA 不是一种内存分配器，而是外设直接访问内存的机制。驱动应该使用 DMA API，例如 `dma_alloc_coherent()` 或其他合适的接口，得到 CPU 访问地址和 `dma_addr_t` 类型的设备访问地址。

```text
CPU 访问：      void *vaddr
设备访问：      dma_addr_t dma_handle
```

在没有 IOMMU、地址空间关系比较简单的系统中，DMA 地址可能与物理地址对应；但在存在 IOMMU 或特殊总线映射时，DMA 地址不一定等于 CPU 看到的物理地址。驱动不能把二者无条件混用。

对于摄像头，videobuf2 可以根据平台选择合适的内存后端，例如 `vb2_dma_contig_memops`。它可能使用 CMA 或 DMA API 提供连续 DMA 内存，但最终是否物理连续、是否经过 IOMMU，还要看具体平台和驱动配置。

## 5. ISP 寄存器

ISP 是 SoC 内部负责图像处理的硬件模块。它通过一组内存映射寄存器配置输入输出格式、DMA 目标地址和中断状态等参数。

设备树通常描述 ISP 的寄存器资源范围，驱动在 `probe()` 中获取资源并通过 `devm_ioremap_resource()` 等接口映射成内核虚拟地址：

```c
base = devm_ioremap_resource(dev, res);

/* 示例，具体偏移和寄存器定义由芯片手册决定 */
writel(format, base + FORMAT_REG);
writel(lower_32_bits(dma_handle), base + DMA_ADDR_LO_REG);
status = readl(base + IRQ_STATUS_REG);
```

映射后的地址只能通过适合设备寄存器的访问接口读写，例如 `readl()` 和 `writel()`。寄存器偏移、位定义以及 DMA 地址寄存器的拆分方式，都要以对应 SoC 的技术手册为准。

## 6. CR3 与 ARM64 页表根

CR3 是 x86 架构中的控制寄存器，保存当前地址空间页表根的地址。进程切换时，内核会切换页表根，后续虚拟地址就按照新进程的页表进行转换。

ARM64 中对应的是 TTBR0 和 TTBR1。通常可以简单理解为：

```text
x86_64  → CR3
ARM64   → TTBR0 / TTBR1
```

因此，同一个虚拟地址在不同进程中可以映射到不同的物理页。内核空间映射则根据架构和内核配置由相应的页表区域管理。

## 7. Camera DMA 的完整链路

以 ISP 把图像写入 DMA buffer，再由用户空间读取为例，整个过程可以按下面的顺序理解。

### 7.1 驱动准备 buffer

驱动或 videobuf2 内存后端分配适合 DMA 的 buffer，得到 CPU 访问地址和设备访问地址：

```text
DMA buffer
  ├── CPU 访问地址：vaddr
  └── 设备访问地址：dma_handle
```

驱动把 `dma_handle` 配置到 ISP 的 DMA 目标地址寄存器中。

### 7.2 用户空间调用 `mmap`

用户通过 V4L2 等接口申请 buffer 后调用 `mmap`。驱动的 `.mmap` 回调把这块 DMA buffer 映射到当前进程的地址空间，返回一个用户虚拟地址。

此时的核心不是复制数据，而是让用户页表中的虚拟地址指向已经存在的 DMA buffer。映射所需的页表可能在映射过程中建立，也可能在后续访问时按需建立，具体取决于映射实现。

### 7.3 ISP 执行 DMA

ISP 使用配置好的 DMA 地址写入内存：

```text
ISP
  → DMA 请求
  → IOMMU（如果平台启用）
  → 物理内存或底层内存页
```

有 IOMMU 时，设备地址会先经过 IOMMU 的 IO 页表转换；没有 IOMMU 时，则由平台的 DMA 地址映射规则直接访问内存。

### 7.4 用户空间读取

用户通过 `mmap` 得到的虚拟地址访问同一个 buffer。CPU 通过当前进程的页表完成地址转换，读到 ISP 已经写入的图像数据。

### 7.5 为什么称为零拷贝

这里的零拷贝是指图像数据没有再从驱动 buffer 复制到另一块用户 buffer，驱动、ISP 和用户空间围绕同一组 DMA buffer 协作。

```text
ISP DMA 写入
      ↓
DMA buffer
      ↑
用户 mmap 读取
```

需要注意，零拷贝不代表系统中永远只有一个物理页，也不代表所有平台的 buffer 都是物理连续的。它强调的是数据路径上没有额外的数据复制，底层可能仍然使用多个物理页、IOMMU 映射和缓存同步操作。

## 8. 总结

- 虚拟地址是 CPU 使用的地址编号，MMU 通过页表把它转换成物理地址。
- 页表通常是多级结构，具体级数、页大小和地址位宽取决于架构及内核配置。
- `mmap` 首先建立虚拟地址区域；设备驱动的 `mmap` 可以把已有的 DMA buffer 映射到用户空间。
- `kmalloc`、`vmalloc` 和 CMA 解决的是不同类型的内存分配问题，DMA 则解决设备如何访问内存的问题。
- `dma_addr_t` 是设备使用的地址，不应该无条件当成 CPU 物理地址。
- ISP 寄存器用于配置硬件，驱动通过设备树提供的资源地址映射并访问它们。
- x86 使用 CR3 保存页表根，ARM64 使用 TTBR0/TTBR1 完成类似工作。
- Camera 零拷贝的关键是驱动、ISP 和用户空间共享同一组 DMA buffer，减少中间复制。
